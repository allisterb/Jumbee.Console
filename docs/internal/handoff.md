# Handoff — end of the 0.1.9 session (2026-08-01)

Living "where we are / what's next" note. Companion to [`eval-findings.md`](eval-findings.md), which is the full
backlog with evidence; this is the short version plus the operational context you'd otherwise have to rediscover.

## Where things stand

**0.1.9 is being packed by the maintainer.** Nine fixes, eight of which came from the jc-curious eval loop rather
than from anyone using the library directly. The load-bearing ones:

- **Braille never rendered in PNG snapshots.** `ToImage` resolved one font for the whole image and only consulted
  `FallbackFontFamilies` when the named font wasn't *installed* — so Consolas (installed, no Braille coverage)
  always won and every Braille cell rasterised as a box. Silent: terminal and text snapshots were fine.
- **`DataTable` highlighted the wrong row** whenever a header wrapped, and mapped clicks to it. Every test
  asserting `SelectedIndex` passed while the UI was visibly wrong.
- **Every second rapid click was swallowed** on nine controls including `Button` — `Control` routes the second
  click of a pair to `OnDoubleClick`, which was an empty virtual on all of them.

Full suite **928/928**. `ProjectAssemblyVersion` is `0.1.9`. Every CHANGELOG 0.1.9 claim was verified present in
the tree before handoff.

## What to pick up next, in order

1. **V-13 — `ControlFrame` can't put a second label on a border edge.** Four separate runs hit this; it's why
   vtop's `─ CPU Usage ──────── 19% ─` can't be expressed and everyone falls back to printing into the content
   area. Highest evidence count of anything still open.
2. **V-28 — `DataTable` has no per-row update, and `Live Data.md` tells you to use one.** The guide says "diff
   against a stable key and update in place"; the control offers only `AddRow`/`RemoveRow`/`Clear`. **This
   contradiction is mine** — either add `UpdateRow(int, params string[])` or correct the guide. Fixing the API is
   better: every live-table app currently rebuilds the whole table each tick and re-finds the selection by string.
3. **V-21 — no proportional split and no layout-changed event.** `SplitPanel.SplitPosition` is absolute cells, so
   "this pane is half the screen" holds only at the size it was tuned for. Only became visible once the layouts
   guide got people building shells that reflow at all.
4. **Cheap doc cross-links, all the same shape** — V-16 (control pages don't name the theme token driving their
   appearance), V-24 (no stated way to turn *off* a control's mouse handling — the V-3 fix answered "is it on?"
   and created this), V-26 (`ConsoleSnapshot`'s mouse API isn't mentioned in "Testing without a terminal", where
   everyone starts), V-19 (`TitleBorderStyle` has no `None`, and the default adds a divider under the title).
5. **V-31 — `DataTable` grid style.** Attempted this session and **reverted**; see `eval-findings.md` for the three
   geometry traps. Short version: don't model Spectre's table layout, *measure* it — `Render` already renders to
   segments and counts them, so derive both the top chrome and the horizontal overhead from the real table and
   delete the `- 1` and `3n + 1` constants before adding any enum.

Also pending, small: fold the reviewer's threading rule into `Live Data.md` — *a control has a single
thread-affine mutation point, and the whole state change plus invalidation crosses the boundary as one unit.*
The guide currently tells the **caller** to marshal; the control owning it is the stronger rule.

## The eval loop

Six cold starts this session, all porting **vtop**. Each ran against a `preview.ps1` snapshot, in its own
workspace under `C:\Users\Allister\Agents\jc-curious\`, forbidden from reading the earlier ones:

`vtop` · `vtop-0.1.8-cold` · `vtop-0.1.9-cold` · `vtop-layouts-cold` · `vtop-livedata-cold` · `vtop-chartdocs-cold`

Only the last two have PNGs generated by a package new enough to render Braille; earlier ones are historical.

**The pattern worth carrying forward.** Five findings — V-1, V-2, V-16, V-20, V-22 — were the *same* defect: the
capability existed and was documented on its own page, and the page a developer starts from didn't mention it.
Every one was fixed by a cross-reference, not new API. V-1 took **four rounds** because the first fix went on
`Plot.md`, which no run ever opened; moving the identical sentence to `Display Widgets.md` and `Live Data.md` had
her find it on the second page she opened. Standing question for any new control page: *what will someone be
holding when they need this, and does that page say so?*

**Three guides were written this session** and all three demonstrably changed behaviour on the next cold start:
`docs/controls/Layouts.md` (first responsive shell in four runs), `docs/controls/Live Data.md` (first run with no
data race, three cadences, correct marshalling), and the chart cross-links above.

## Operational notes

- **Agent `.md` edits need a session reload.** If you spawn without one, restate the brief in the prompt or the
  agent will run the *previous* target's assignment.
- **Forbid the prior workspaces explicitly in every re-run.** jc-curious has `Read`; a peek voids the measurement.
- **Verify agent-reported numbers before acting.** Two reviewers gave confident, precise, mutually incompatible
  figures for the same sampling loop (23 ms/tick vs 9.8 s/pass); direct measurement said ~17 ms, of which ~12 ms
  is `Process.GetProcesses()` itself and ~5 ms is 190 access-denied throws.
- **Reproduce in the configuration the bug was reported from.** V-22 passes in an isolated test *with the bug
  present* and only fails once other renders have run in the same process — which is why it survived three rounds
  and why I twice drew the wrong conclusion from single-test runs.
- The `--test` harness in each workspace regenerates that run's PNGs; re-point its `PackageReference` at a newer
  preview first or you'll re-render with the old package.
